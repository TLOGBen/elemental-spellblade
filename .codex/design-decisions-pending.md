# v0.3_alter 待併入的使用者決定（2026-09-20，Fable 撞到用量上限後累積）

Fable 的 session 限制在 21:30 重置。恢復後把這些併進 `元素魔戰士規劃-v0.3_alter.md`
與 `design-latency-2026-09-20.md`，並沿用先前已交代的全部決定。

## 1. 毒素：先不與毒藥合併，改為「強度與時間一起長」的單一效果

使用者收回「與煉金毒藥結合」的方向（留待日後），毒素維持自有效果，但不用階梯、不數層。

指揮官已驗證可行（`vendor/imports/ActiveMagicEffect.psc`）：
- `float Function GetMagnitude() native`（362 行區塊附近：`GetDuration`、`GetTimeElapsed`）
- 所以「疊加」＝讀目標身上該效果目前的強度與已過時間 → 算出新強度與新時長 → 以同一顆效果重新套用。
- 狀態存在目標自己的 active effect 上，沒有陣列、沒有狀態宿主、沒有匯出匯入，180126 那類跨目標污染不可能發生。

要 Fable 定的：每次命中的強度增量與上限、時間延長量與上限、命中刷新的計算式、
催毒在這個模型下的表示法、以及與 2.7 公式的接法。

## 2. 毒素：目標死亡時把「剩餘傷害」傳遞出去

剩餘傷害 = 目前強度 × 剩餘秒數（兩者都讀得到）。死亡時傳給附近一名敵人，
換算回強度與時長。指揮官建議傳遞打折（約 0.7）讓鏈條收斂，需使用者確認折扣值。
這條接上毒素「唯一會擴散」的定位。

## 3. 冰霜：斬殺改為「凍結中被擊中 → 最大生命 20% 真實傷害」

取代原本「凍結量表滿 5 且生命低於 20% 才處決」。真實傷害不吃抗性。
指揮官建議首領另給折扣（例如 8%），需使用者確認。

## 4. 神聖與黑暗：死亡機制改為「死時身上有沒有該印記」

- 死亡時身上有神聖印記 → 化灰；有黑暗印記 → 復生。雙印時化灰優先（沿用 v0.3）。
- 因此整套「擊殺歸屬」機制刪除：`LastDamageFor`／`LastDamageWasElement`、
  `RegLastDamage[8]`、`DamageActor[128]`／`DamageElement[128]`、
  `kill_attribution_seconds`，以及 round 10 與 round 14 為此加的全部路徑。
- 判定改為死亡當下的 `HasMagicEffect`。
- 需在文件中說明：物理一擊秒殺、來不及掛印記者不觸發（可接受）。

## 已在前面交代、Fable 尚未寫完的部分（恢復後一併完成）

## 5. 毒素的死亡傳遞：全場擴散，每跳衰減 50%（使用者 2026-09-20，已定案）

中毒目標死亡時，附近**所有**合格敵人各接收一份毒（使用者明確要「一隻死全場中毒」）。
每份的總量 = max(該效果的剩餘傷害, 死亡者最大生命 × 30%) × 50%，再換算回強度與時長。
連鎖成立且刻意保留：接收者若也毒死，同一規則再跑一次，因此每跳 50% 會自然收斂
（滿血敵人通常擋得住 0.15×H 的一跳）。不另加跳數上限或去重，除非 Fable 能舉證會失控。
待定的數字：死亡擴散半徑。指揮官建議沿用規劃的「附近」15 公尺，一般命中擴散維持 3 公尺。

## 6. 冰霜斬殺對首領：10%（使用者 2026-09-20）

一般目標最大生命 20%，首領與必要角色 10%，皆為真實傷害。

## 7. 雷電：保留隨機，改為「依電荷量擲 N 次取最大」（使用者 2026-09-20）

- 附傷仍是 1～25 的隨機，但擲骰次數隨玩家當前電荷階數增加，取其中最大值。
- 期望值（均勻 1～25）：擲 1 次 13.0、2 次 17.3、3 次 19.5、4 次 20.8。
  低值仍可能出現，只是隨電荷變稀有；雷「落差最大」的個性保留，而且和電荷資源接上。
- 實作限制：引擎套用的法術強度是固定的，每擊隨機只能用「機率條件的多段進入點」表達
  （`GetRandomPercent` 類條件）。請 Fable 給出每個電荷階的條件段設計，使實際分布
  近似「擲 N 次取最大」，並說明近似誤差；若進入點段數成本過高，提出替代的離散分布。
- 這取代先前「附傷固定為區間平均值」（原 16 條決定清單第 5 條）；其餘元素是否保留隨機由 Fable 提建議。

## 8. 神聖：打帶印記的目標會強化「你自己」（使用者 2026-09-20）

神聖的定位從「對目標的裁決＋回血」轉為**自我強化**：命中帶有神聖印記的目標時，
玩家身上的神聖階梯前進一階（同樣是互相取代的效果，不數層），提供遞增的自身增益，
停止攻擊就自然退回。頂階要有明顯的回報。

使用者定調：**聖武士感，打越久越痛**——自身階梯以「成長的攻擊力」為主軸，治療與防禦是附帶，不是重點。
神聖因此成為「持久戰」元素，和風（一擊即走）、雷（爆發）在定位上分開。

指揮官提出的形狀，待 Fable 補完數值並待使用者確認：
- 三階自身效果（例如 聖佑 I／II／III），主軸是遞增的武器傷害與聖傷，護甲與回復為附帶。
- 每階有自己的持續時間，命中帶印記的目標才會刷新；停手就逐階退回，不是瞬間歸零。
- 頂階要有明顯的回報（例如額外的聖屬傷害、對亡靈魔族再加成、武器聖光更盛）。
- 進階條件是「命中身上有神聖印記的目標」，不是任意命中，所以要先掛印記才能養。
- 保留 v0.3 既有的神聖特色：對亡靈魔族加成、擊殺化灰（現在改看死時是否帶神聖印記）、治療。
- 與決定 14（PERK 進入點的條件分頁可讀目標狀態）相合：自身階梯讀自己身上的效果更便宜。
- 需 Fable 說明：原本 5.9 樹中依賴「聖印層數」的節點如何改寫，以及裁決／天啟等終焉是否保留。

## 9. 風：終焉改為「多段觸發」——讓接管的元素連續觸發 N 次（使用者 2026-09-20）

風的定位從「自己打很多段」擴充為「**讓別的元素打很多次**」。
目標身上有風印記時切換元素，風的終焉讓**接管元素的命中效果連續觸發 N 次**。

這讓風與水、星形成一組鋪場元素：水加強度（下一次終焉 ×1.5）、星加開場（接管的開印 ×1.5）、
風加次數（接管的命中 ×N 次）。

因為所有狀態都改成階梯，N 次觸發對不同元素的結果天然不同，這是刻意保留的設計空間：
冰＝一次推到冰封、火＝直接白熱近乎立即引爆、毒＝強度與時間一次拉高、
神聖＝自身聖佑一次跳數階、雷＝N 次獨立擲骰等於一次爆發。

待 Fable 決定並補完：
- N 的成長曲線（指揮官建議基礎 2 次，風樹節點往上加，後期 4～5 次），以及是否需要上限
  （傷害型元素吃 N 次等於 N 倍傷害，必須有天花板）。
- 原本風的終焉「吹飛」保留或取代。指揮官傾向保留吹飛為基礎行為，多段觸發放在
  風的關閉路線後期節點，讓前後期有區隔。
- 「連續觸發 N 次」在引擎側怎麼表達（PERK 進入點套用 N 次 vs 其他方式），以及每次觸發的成本。
- 與 5.7 風樹既有節點（風勢、風刃、千刃、連殺）的關係，哪些被取代。
